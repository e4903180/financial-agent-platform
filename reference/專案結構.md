一個企業級、遵循 MLOps 最佳實踐且與 LangChain/微調解耦的專案，其目錄結構設計必須同時兼顧 **「應用程式開發（LangChain Agent）」** 與 **「模型訓練管線（Azure ML / QLoRA）」**。

## 💡 關鍵架構設計說明

### 1. 將 train/ 與 agent/ 徹底解耦（分離 CI/CD 與 Runtime）

* src/train/ 是**一次性或週期性**執行的管線。它的任務是跟 Azure ML 溝通，把雲端算力叫起來、跑完 QLoRA、把幾百 MB 的 LoRA 權重推回私有庫，然後算力叢集就可以關閉省錢。
* src/agent/ 是**常駐型**的後端服務（Runtime）。它只負責監聽使用者請求，並透過 model_factory.py 去調用已經訓練好的成果，兩者互不干擾。

### 2. 獨立出 src/database/ 作為基礎設施隔離

* 不要把 SQL 連線或 Azure AI Search 的 SDK 呼叫直接寫在 LangChain 的 Tool 裡面。
* 把資料庫的連線池管理、安全性稽核（阻斷 DROP 指令）寫在 database/azure_sql.py 裡，再讓 agent/tools/sql_tool.py 去引入。這樣未來如果資料庫從 Azure SQL 換成 PostgreSQL，你只需要修改 database/ 的程式碼，完全不會動到 Agent 的核心邏輯。

### 3. 設定檔集中化（config/）

* 任何調整（例如：微調的 Learning Rate、模型的 Temperature、或是 RAG 要撈取的前幾筆資料 top_k）都應該寫在 config/ 的 YAML 檔中，絕對不要硬編碼（Hardcode）在 src/ 的程式碼裡。這能讓 MLOps 工程師在不改動程式碼的情況下，直接調整系統行為。
